## 1. Reproduced defects and root causes

| # | Symptom | Root cause | Fix |
|---|---|---|---|
| 1 | `/products` showed 53 vs 67, no "jali" results, one Tata filter, no language switch (until refresh) | `next.config.mjs` media cache rule `/products/:path*` (also `/brands`, `/blog`) matched the **page routes**, so their HTML was served `Cache-Control: public, max-age=604800, stale-while-revalidate=2592000`. Verified on live with `curl -I`: `/products`, `/products/binding-wire`, `/brands`, `/blog` had it; `/`, `/hi/*`, `/categories/*`, `/contact` did not. - **Counts**: /products lists each product once under its own category: 53 products, 53 rows, filtered counts equal rows shown.
- Phone hero capped at 40 rem tall so the next section starts in view; eyebrow contrast raised.
- Captions: `content/captions.ts` renders `<track>` when a file is listed. None are, see 4.
- GA: `gtag.js` loads on idle; a 5-line stub keeps events queued.

## 3. Measurements

Lighthouse 12, mobile preset (simulated 4G / 4x CPU), headless Chrome on one Mac. Median of 3 unless noted.

Production (`https://www.hmibrahim.net/`, before changes, 3 runs): perf 91 / 70 / 90, LCP 3.5 / 5.9 / 3.7 s (the 70 run: lazy logo), FCP 1.4 / 3.7 / 1.1 s, TBT 15-30 ms, CLS 0.

Local production build (`next start`), same machine, same settings, so only comparable with each other, not with production:

| Page | Before perf / LCP / bytes | After perf / LCP / bytes |
|---|---|---|
| Home | 83 / 4.36 s / 731 KB | 91 / 3.46 s / ~440 KB |
| /products | 80 / 4.88 s (runs 80, 80, 90) | 92 / 3.31 s |
| /products/binding-wire | 75 / 6.5 s | 90 / 3.54 s |
| /contact | 88 / 3.76 s (1 run) | 96 / 2.86 s |
| /hi (Hindi home) | 83 / 4.36 s (1 run) | 84 / 4.21 s |

Accessibility, best practices, SEO stayed 100. Unthrottled local LCP is about 0.1 s; the simulated LCP is dominated by bytes ahead of it (JS ~170 KB, fonts ~100 KB).

**Not met**: lab LCP <= 2.5 s on home (3.5 s) and Hindi pages (4.2 s: Hindi must load the 121 KB Devanagari font). One early /products run showed a 500 ms task and one binding-wire run 57; neither reproduced in re-runs. No production or preview measurement after the change exists, and lab data is not a real-user Core Web Vitals result. Remaining ideas: inline critical CSS (needs `critters`), subset the Devanagari font, split the home page's below-the-fold client components.

## 5. Deploy steps

1. Review and merge the branch; deploy to a Vercel preview first and re-run Lighthouse there.
2. After the production deploy the CDN serves fresh HTML (new deployment). **Browsers that already stored `/products`, `/products/*`, `/brands` or `/blog` with `max-age=604800` will keep that copy until it expires (up to 7 days); there is no server-side way to clear it.** A hard refresh clears it for one visitor.
3. Confirm `NEXT_PUBLIC_GA_ID` and the quote mail/sheet variables are set in Vercel, and send one real test enquiry yourself.
4. Run `npm test` (32 tests) and `npx tsc --noEmit` before merging.
